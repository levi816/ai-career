# AI Career Copilot Document Governance v0.1

版本：v0.1

用途：

定义 AI Career Copilot 项目中文档的优先级、维护规则和变更流程。

目标：

确保产品、设计、技术和开发基于统一信息源工作，避免范围漂移和文档冲突。

------------------------------------------------------------------------

# 1. 文档管理原则

## 1.1 Single Source of Truth

项目中所有关键决策必须存在唯一事实来源。

当多个文档出现冲突时，必须按照本文档定义的优先级执行。

------------------------------------------------------------------------

# 2. 文档优先级

从高到低：

    Product Decision Log

    ↓

    PRD

    ↓

    AI Output Specification

    ↓

    Technical Architecture

    ↓

    Figma Prototype Requirement

    ↓

    Development Task Breakdown

    ↓

    Codex Development Prompt

    ↓

    README

------------------------------------------------------------------------

# 3. 各文档职责

## 3.1 Product Decision Log

优先级最高。

负责记录：

-   MVP范围
-   功能取舍
-   重大产品决策
-   冲突解决方案

示例：

如果决定：

"MVP不支持音频面试分析"

则所有文档必须同步。

------------------------------------------------------------------------

## 3.2 PRD

负责定义：

产品需要做什么。

包含：

-   用户需求
-   功能范围
-   用户流程
-   产品规则

不负责：

-   技术实现
-   UI细节

------------------------------------------------------------------------

## 3.3 AI Output Specification

负责定义：

AI如何输出结果。

包含：

-   输入格式
-   JSON Schema
-   字段定义
-   异常处理
-   用户反馈机制

所有AI功能开发必须遵守。

------------------------------------------------------------------------

## 3.4 Technical Architecture

负责定义：

系统如何实现。

包含：

-   技术架构
-   数据模型
-   服务设计
-   API原则

必须遵循PRD中的MVP范围。

------------------------------------------------------------------------

## 3.5 Figma Prototype Requirement

负责定义：

产品界面和交互。

限制：

Figma不能新增PRD之外的功能。

------------------------------------------------------------------------

## 3.6 Development Task Breakdown

负责定义：

开发顺序和任务拆解。

包含：

-   Sprint
-   Task
-   验收标准

不能自行扩大需求。

------------------------------------------------------------------------

## 3.7 Codex Development Prompt

负责指导AI Coding工具执行开发。

不是产品决策来源。

------------------------------------------------------------------------

# 4. 冲突处理规则

## Figma与PRD冲突

以PRD为准。

例如：

Figma存在录屏分析，但PRD没有。

处理：

删除或调整Figma。

------------------------------------------------------------------------

## Technical Architecture与PRD冲突

以PRD为准。

技术方案需要更新。

------------------------------------------------------------------------

## Development Task与PRD冲突

开发任务需要调整。

------------------------------------------------------------------------

# 6. 文档版本管理

版本格式：

    文档名_v版本号

例如：

    PRD_v0.2

重大范围变化：

升级版本。

小修改：

增加小版本号。

------------------------------------------------------------------------

# 7. 文档修改流程

任何重大修改：

必须经过：

    提出问题

    ↓

    记录Decision Log

    ↓

    更新相关文档

    ↓

    重新Review

    ↓

    进入开发

禁止：

只修改单个文档导致冲突。

------------------------------------------------------------------------

# 8. Codex使用规则

Codex开发前必须阅读：

    Document Governance

    Product Decision Log

    PRD

    AI Output Specification

    Technical Architecture

    Development Task Breakdown

    Codex Prompt

如果发现冲突：

Codex必须：

1.  停止开发。
2.  指出冲突。
3.  等待确认。

禁止：

自行扩大需求。

------------------------------------------------------------------------

# 9. Figma使用规则

设计必须基于：

Figma Prototype Requirement。

发现新需求：

流程：

    提出需求

    ↓

    更新PRD

    ↓

    更新Figma

    ↓

    开发

------------------------------------------------------------------------

# 10. 功能验收规则

每个功能完成必须满足：

产品层：

符合PRD。

AI层：

符合AI Output Specification。

技术层：

符合Technical Architecture。

设计层：

符合Figma。
