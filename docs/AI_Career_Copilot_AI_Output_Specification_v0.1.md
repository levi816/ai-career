# AI Career Copilot AI Output Specification v0.1

版本：v0.1

用途：

定义 AI Career Copilot MVP 阶段所有 AI
能力的输入、输出、数据结构、异常处理和用户反馈机制。

目标：

让 AI 输出可稳定展示、可追踪、可优化。

------------------------------------------------------------------------

# 1. AI输出设计原则

## 1.1 结构化输出

所有 AI 服务必须返回固定 JSON Schema。

禁止：

-   直接返回无法解析的自然语言
-   不同请求返回完全不同结构

------------------------------------------------------------------------

## 1.2 可解释性

AI结论必须包含：

-   判断依据
-   相关用户信息
-   不确定性说明

------------------------------------------------------------------------

## 1.3 避免虚假精确

MVP不展示：

"录取概率85%"

"岗位匹配85%"

改为：

-   Match Level
-   Confidence
-   Evidence

------------------------------------------------------------------------

# 2. Career Planning AI

## 功能目标

根据用户背景生成职业方向建议。

## 输入

User Profile：

``` json
{
"education":"",
"major":"",
"skills":[],
"experience":[],
"career_goal":""
}
```

------------------------------------------------------------------------

## 输出 Schema

``` json
{
"career_direction":"",
"recommended_roles":[
{
"role":"",
"reason":""
}
],

"strengths":[
{
"skill":"",
"evidence":""
}
],

"gaps":[
{
"gap":"",
"reason":""
}
],

"improvement_suggestions":[
""
]
}
```

------------------------------------------------------------------------

## 字段说明

career_direction：

推荐职业方向。

recommended_roles：

推荐岗位列表。

strengths：

用户已有优势。

gaps：

岗位要求与用户能力差距。

improvement_suggestions：

能力提升建议。

------------------------------------------------------------------------

``` json

{
"section":"",

}
],

"suggestions":[
{
"original":"",
"optimized":"",

```

------------------------------------------------------------------------

## 注意

------------------------------------------------------------------------

# 4. JD Matching AI

## 功能目标

分析用户与岗位需求的匹配情况。

## 输入

JD

-   

User Profile

-   

Resume

------------------------------------------------------------------------

## 输出 Schema

``` json
{
"match_level":"",

"confidence":"",

"evidence":[
{
"requirement":"",
"status":"",
"user_evidence":""
}
],

"gaps":[
{
"requirement":"",
"missing":"",
"suggestion":""
}
]
}
```

------------------------------------------------------------------------

## Match Level定义

Strong Match：

已有明显相关经历。

Partial Match：

部分符合，需要补充。

Weak Match：

核心能力缺失。

------------------------------------------------------------------------

## Confidence定义

High：

用户信息充分。

Medium：

存在部分未知。

Low：

信息不足。

# 8. AI错误处理规范

## 8.1 模型调用失败

返回：

``` json
{
"status":"error",
"code":"MODEL_ERROR",
"message":"AI服务暂时不可用，请稍后重试"
}
```

------------------------------------------------------------------------

## 8.2 信息不足

返回：

``` json
{
"status":"warning",
"code":"INSUFFICIENT_DATA",
"message":"当前信息不足，无法准确分析"
}
```

------------------------------------------------------------------------

## 8.3 超时

处理：

-   自动重试一次
-   失败后返回友好提示

------------------------------------------------------------------------

# 9. 用户纠正机制

AI输出后允许用户反馈。

例如：

AI：

"缺少数据分析经验"

用户：

"我有SQL项目经历。"

保存：

``` json
{
"report_id":"",
"user_correction":"",
"created_time":""
}
```

用途：

未来优化：

-   用户画像
-   Prompt
-   推荐逻辑

------------------------------------------------------------------------

``` json
"temperature":"",

```

目的：

支持：

-   效果评估
