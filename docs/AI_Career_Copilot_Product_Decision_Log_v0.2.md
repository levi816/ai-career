# AI Career Copilot 产品修订决策文档（Product Decision Log v0.2）

版本：v0.2

目的：

根据 Codex 技术评审反馈，对 AI Career Copilot
项目范围、功能定义、AI能力和技术实现进行统一决策。

本文档作为后续 PRD、技术架构和开发任务拆解的最高优先级参考。

------------------------------------------------------------------------

# 1. MVP范围重新定义

## 1.1 产品愿景（Vision）

AI Career Copilot 的长期目标：

帮助用户完成完整职业发展闭环：

    职业规划

    ↓

    简历优化

    ↓

    岗位匹配

    ↓

    投递管理

    ↓

    面试复盘

    ↓

    Offer决策

    ↓

    职业成长

以上作为产品长期方向保留。

------------------------------------------------------------------------

# 1.2 MVP v1.0范围冻结

MVP目标：

验证 AI 是否能够帮助求职者完成核心求职闭环。

MVP包含：

    用户画像

    ↓

    AI职业规划

    ↓

    AI简历助手

    ↓

    JD智能匹配

    ↓

    Application投递管理

    ↓

    AI面试复盘

------------------------------------------------------------------------

# 1.3 暂缓功能

## P1版本

后续实现：

-   Offer决策助手
-   Growth Center

原因：

这些功能依赖更多用户数据积累。

------------------------------------------------------------------------

## P2版本

长期能力：

-   高级Memory
-   RAG知识库
-   AI Agent主动执行

------------------------------------------------------------------------

# 2. 产品核心对象调整

## Decision：Application继续作为核心对象

原因：

用户真正管理的是求职机会，而不是AI聊天记录。

结构：

    Application

    ↓

    JD

    ↓

    Resume

    ↓

    Interview

    ↓

    Offer

------------------------------------------------------------------------

# 3. Memory能力调整

## 原决策

Memory属于P2。

## 新决策

调整为：

MVP基础能力。

------------------------------------------------------------------------

## MVP不实现

复杂：

-   向量记忆
-   自动召回Memory
-   Agent Memory

------------------------------------------------------------------------

## MVP实现

结构化用户上下文。

包括：

## User Profile Memory

保存：

-   教育背景
-   技能
-   求职目标
-   经历

## Application Memory

保存：

-   JD
-   匹配结果
-   投递状态

## Interview Memory

保存：

-   面试问题
-   回答
-   AI反馈

## Decision Memory

保存：

-   用户选择
-   决策原因

------------------------------------------------------------------------

# 4. 功能冲突统一规则

## 4.1 行动计划

原：

Career Planning包含行动计划。

调整：

删除"行动计划"。

改为：

## 能力提升建议

输出：

-   当前能力
-   岗位要求
-   能力差距
-   提升方向

------------------------------------------------------------------------

# 4.2 面试输入方式

## MVP

支持：

文本输入。

用户手动记录：

-   面试问题
-   自己回答

------------------------------------------------------------------------

## 后续版本

V1.5：

音频上传 + ASR转文字。

V2：

录屏分析。

------------------------------------------------------------------------

# 4.3 投递状态统一

采用：

简单状态 + Timeline。

## 用户展示状态

    待投递

    已投递

    面试中

    Offer

    已结束

## Timeline详细记录

例如：

    HR沟通

    ↓

    一面

    ↓

    二面

    ↓

    终面

------------------------------------------------------------------------

# 4.4 自定义状态

保留。

MVP实现：

默认状态 + custom_status字段。

暂不开发复杂工作流。

------------------------------------------------------------------------

# 5. AI输出规范要求

新增：

AI Output Specification。

所有AI能力必须定义：

-   输入格式
-   输出JSON Schema
-   错误处理
-   用户纠正机制

------------------------------------------------------------------------

## 示例：JD分析输出

``` json
{
  "match_score": 85,
  "strengths": [
    "产品经验"
  ],
  "gaps": [
    "LLM基础不足"
  ],
  "suggestions": [
    "补充AI项目经验"
  ]
}
```

------------------------------------------------------------------------

# 5.1 AI异常处理

## 模型失败

返回：

"AI服务暂时不可用，请稍后重试。"

------------------------------------------------------------------------

## 信息不足

返回：

"当前信息不足，无法进行准确分析。"

禁止模型编造。

------------------------------------------------------------------------

# 6. 数据模型调整原则

## 原问题

------------------------------------------------------------------------

## 新原则

避免：

------------------------------------------------------------------------

------------------------------------------------------------------------

## ApplicationTimeline

记录状态变化。

------------------------------------------------------------------------

# 7. 文件处理范围调整

## MVP原则

优先验证AI价值。

------------------------------------------------------------------------

## MVP暂不实现复杂解析：

暂缓：

-   PDF解析

## MVP输入方式

优先：

------------------------------------------------------------------------

# 8. 隐私与安全要求

新增：

Security & Privacy设计。

------------------------------------------------------------------------

必须支持：

## 数据隔离

不同用户数据不可访问。

## 删除机制

用户可以删除：

-   简历
-   面试记录
-   账号数据

## 文件权限

用户只能访问自己的文件。

## 数据脱敏

日志中禁止输出：

-   简历内容
-   联系方式
-   薪资隐私

------------------------------------------------------------------------

# 9. AI主动能力调整

## 原设计

AI主动助手。

调整：

MVP不做Agent。

------------------------------------------------------------------------

## MVP实现

规则触发 + AI生成建议。

例如：

规则：

7天没有更新投递。

↓

AI生成：

"建议关注当前求职进度。"

------------------------------------------------------------------------

# 10. 模型架构决策

Provider抽象。

架构：

    Business Layer

    ↓

    AI Service

    ↓

    ↓

    GPT / Qwen / DeepSeek
